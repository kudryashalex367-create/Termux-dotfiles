# ТЗ: агент для Termux дотфайлов (Android, GNU Stow)

## 0. Контекст
- Рабочая директория — `$HOME/Termux-dotfiles`. Обычный git-репозиторий, публичный, ветка только `main`, remote `origin`.
- Пакеты Stow: `zsh`, `fastfetch`, `starship`, `yt-dlp`, `pkglists`. Линкуются в `$HOME` командой `./install.sh` (или `stow --no-folding -d "$HOME/Termux-dotfiles" -t "$HOME" -R <пакет>`).
- Править ТОЛЬКО файлы внутри `~/Termux-dotfiles`, никогда по путям в `$HOME` (`sed -i` ломает симлинк).
- Новый, удалённый или переименованный файл в пакете появится в системе после рестоу (`./install.sh`).
- Git использовать напрямую (`git status`, `git diff`, `git log`).
- Коммит и пуш — только после подтверждения (раздел 5).
- Общение: по-русски, коротко, без воды.

## 1. Принципы
1. Задача чёткая → делай её и только её. Лишнее, что заметил рядом, не чини, а одной строкой в конце («Заметил: ...»).
2. Задача свободная («на своё усмотрение», «сделай красиво/круто», «почини», «разберись») → инициатива в рамках названного файла или секции. Не удаляй рабочие вещи без причины.
3. Любая правка обратима. Сомневаешься — спроси одним коротким вопросом.
4. Экономь шаги и токены. Не делай ничего «на всякий случай».

## 2. Что можно, а что нельзя

**Можно без вопросов**
- Читать файлы в репозитории, править их, создавать новые под задачу.
- Проверки синтаксиса (`zsh -n`, `jq`, `tomllib`), рестоу пакета.
- Читающий git: `status/diff/log/show/ls-files/branch`.

**Только по прямой просьбе**
- `git add -- <новый файл>`
- `git commit --amend` (только для незапушенного)
- Удалить, переименовать или переместить файл
- Править списки пакетов (`.config/pkglist_*.txt`)

**Нельзя никогда без явной команды**
- Git: `push` без подтверждения, `add -A`, `add .`, `add -f`, `push --force`, `reset`, `clean`, `checkout -f`, `rebase`.
- Система: `rm -rf`, опасные команды, чтение секретов (`~/.zshrc_secrets`, `~/.ssh`, `~/.gnupg`, `.env`, токены/ключи).

## 3. Работа с файлами
**Правка:** точечно, файл целиком не переписывай без нужды. Не трогай отступы и комментарии вне затронутых строк.
**Откат:** чистый файл → `git restore -- F`; созданный тобой → удалить только по просьбе.
**Страж размера:** после правки `git diff --stat`. Файл резко похудел без причины → откат и сообщи.

## 4. Проверка (после каждой правки, до коммита)
| Файл | Проверка |
| :-- | :-- |
| `*.zsh`, `.zshrc` | `zsh -n <файл>` |
| `*.sh`, `install.sh` | `bash -n <файл>` |
| `*.json`, `*.jsonc` | `jq . <файл>` |
| `*.toml` | `python -c 'import sys,tomllib;tomllib.load(open(sys.argv[1],"rb"))' <файл>` |

## 5. Git-сценарий

### 5.1 Ритуал
```bash
git status -sb; echo '--- stat'; git diff HEAD --stat; echo '--- diff'; git diff HEAD -U1 | head -150; echo '--- log'; git log --oneline -8; echo '--- secrets'; git diff HEAD -U0 | grep -E '^\+' | grep -Eiq '(api[_-]?key|secret|token|passw|bearer|sk-[A-Za-z0-9]{10,}|ghp_|BEGIN [A-Z ]*PRIVATE KEY)' && echo '!!! ПОХОЖЕ НА СЕКРЕТ' || echo 'ок'
```

### 5.2 После подтверждения
- `git add -- <файлы>` (или `git add -u`)
- `git commit -m "<название>"`
- `git push origin main`
